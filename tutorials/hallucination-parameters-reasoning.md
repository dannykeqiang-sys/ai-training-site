# 幻觉、参数量与推理能力

本篇讨论大语言模型的三个核心认知：它会犯错（幻觉）、大不一定好（参数量）、以及它正在学会"思考"（推理能力）。理解这三点，才能对 LLM 建立正确的期望。

## 一、幻觉（Hallucination）

### 1.1 定义

**幻觉（Hallucination）** 指大语言模型生成的内容**看起来流畅合理，但实际上是错误的、虚构的、或无中生有的**。[¹](#ref1) [²](#ref2)

典型表现：
- 编造不存在的论文引用（虚假 DOI、虚构作者）
- 给出看似专业但完全错误的医学/法律建议
- 信誓旦旦地说出一个不存在的 API 函数名

### 1.2 根本原因

![幻觉的产生机制：流畅不等于真实](https://yk-ai-mentor.youku.com/yk_ai_mentor/tutorials/ch1/images/hallucination-causes_1784688690.png)

大模型产生幻觉的根本原因是：**它本质上是一个基于概率的"文字接龙"系统，而不是一个知识检索系统。**[¹](#ref1) [²](#ref2) [³](#ref3)

具体来说：

1. **概率续写，不是事实查询**：模型学到的是"在什么上下文之后，什么 Token 出现的概率高"，而非"哪个事实是真的"。当训练数据中缺乏足够约束时，模型会根据统计模式"编"一个看起来合理的续写。

2. **没有内置事实校验机制**：模型没有"知道自己不知道"的能力（缺乏 calibration），不会在不确定时拒绝回答。

3. **训练数据噪声**：互联网语料本身包含错误信息，模型学到错误内容后也会高置信度输出。

4. **生成过程的"滚雪球效应"**：一旦前几个 Token 偏离事实轨道，后续 Token 会基于错误前提继续续写，使错误越来越离谱。

> OpenAI 2025 年发布的研究论文《Why Language Models Hallucinate》系统分析了幻觉的 16 种成因类别。[³](#ref3)

### 1.3 幻觉的分类

学术界通常将幻觉分为两大类：[³](#ref3)

| 类型 | 定义 | 示例 |
|---|---|---|
| **内在幻觉（Intrinsic）** | 生成内容与输入源文本/上下文矛盾 | 文档说"2024年收入增长5%"，模型总结为"收入下降" |
| **外在幻觉（Extrinsic）** | 生成内容无法从任何输入信息中验证，凭空编造 | 问"这篇论文的作者是谁"，模型编造了一个不存在的名字 |

在实际应用中，外在幻觉更常见也更危险，因为它看起来完全"合理"却无法验证。

从使用者角度，你更常遇到的是：(1) **事实性错误**——编造不存在的事实；(2) **逻辑性错误**——推理链条断裂；(3) **过度自信**——不确定时不承认，反而编造。

### 1.4 缓解手段（非消除）

| 手段 | 原理 |
|---|---|
| **RAG（检索增强生成）** | 让模型基于检索到的真实文档回答，减少"编造" |
| **降低 Temperature** | 减少低概率 Token 被采样，输出更保守 |
| **要求引用来源** | Prompt 中要求模型标注信息来源，便于验证 |
| **Grounding / 事实验证** | 在输出后增加一个校验步骤 |
| **让模型说"我不知道"** | 通过 System Prompt 引导模型在不确定时承认无知 |

> 对于日常使用，最有效的两个手段是：(1) 在 Prompt 中提供参考材料（RAG 或直接粘贴文档），让模型有据可依；(2) 在 System Prompt 中明确告诉模型"如果不确定请说不知道"。

> 重要认知：**幻觉无法被彻底消除**，只能被降低和管控。这是概率模型的本质限制。

了解了模型会犯错之后，一个自然的想法是：用更大的模型能不能解决这个问题？答案是没有那么简单。

## 二、参数量越大越好？——Scaling Laws 的启示

### 2.1 题面核心

> "参数量越大的模型，在所有任务上一定表现越好。" 这个说法是否正确？

**答案：不正确。**

### 2.2 Scaling Laws 的发现

2020 年 OpenAI 发表了经典论文《Scaling Laws for Neural Language Models》，发现模型性能（loss）与三个因素呈幂律关系：[⁴](#ref4)

1. **参数量（N）**
2. **训练数据量（D）**
3. **计算量（C）**

2022 年 DeepMind 的 **Chinchilla 论文** 进一步指出：给定固定计算预算，参数量和训练数据量应该**同比例扩大**，而非一味增大参数。[⁵](#ref5)

> Chinchilla（70B 参数）在多项基准上击败了 Gopher（280B），证明"更大不等于更好"。

### 2.3 为什么"参数量越大越好"是错的

| 反例 | 说明 |
|---|---|
| **数据不足时大模型反而更差** | 参数多但训练数据少 → 过拟合，泛化性下降 |
| **小模型 + 好数据 > 大模型 + 差数据** | Chinchilla/Phi 系列的成功 |
| **特定任务不需要大模型** | 情感分类等简单任务，7B 模型可能和 70B 表现一样 |
| **推理成本** | 大模型推理慢且贵，实际业务中有性价比考量 |
| **Mixture of Experts (MoE)** | DeepSeek-V3（235B 总参数但每次只激活 37B）说明"有效参数"才是关键 |

### 2.4 真实案例：参数量 vs 实际表现

| 模型 | 参数量 | 关键特点 | 性能表现 |
|---|---|---|---|
| Chinchilla (2022) | 70B | 数据量 4x 于同等参数模型 | 超越 280B 的 Gopher |
| Phi-2 (Microsoft) | 2.7B | 精选高质量教科书数据 | 在推理任务上接近 13B 模型 |
| Llama 3.1 8B | 8B | 15T tokens 训练数据 | 超越早期 70B 模型 |
| Qwen3-235B (MoE) | 235B 总/37B 激活 | MoE 架构 | 接近 GPT-4 水准但推理成本低 |

这些案例都说明：**模型能力 = f(参数量, 数据质量, 数据量, 训练方法)**，而非单纯由参数量决定。

### 2.5 正确认知

- 参数量是影响模型能力的**重要因素之一**，但不是唯一因素
- 训练数据质量、数据量、训练方法（RLHF、DPO 等）同样关键
- 在工程实践中应根据任务需求选择**合适规模**的模型

参数量和数据质量决定了模型的"知识储备"，但面对需要深度思考的问题，光有知识还不够。接下来我们看看模型如何学会"推理"。

## 三、大语言模型的推理能力（Reasoning）

### 3.1 什么是 LLM 的"推理能力"

在 AI 领域，**推理能力（Reasoning Capability）** 指模型执行逻辑推理、数学计算、多步规划、因果分析等需要"思考"的任务的能力。[⁶](#ref6)

> 注意与"Inference（模型推理/前向计算）"区分——这里讨论的是模型的认知推理能力。

### 3.2 传统 LLM 的推理局限

标准的自回归 LLM 存在天然推理瓶颈：
- 每个 Token 的生成只用了固定量的计算（一次前向传播）
- 模型倾向于"跳步"直接给答案，而不是逐步推导
- 复杂数学、逻辑链条容易在中间步骤出错

### 3.3 推理模型（Reasoning Model）的突破

![传统 LLM 与推理模型的对比](https://yk-ai-mentor.youku.com/yk_ai_mentor/tutorials/ch1/images/reasoning-model-compare_1784688719.png)

2024-2025 年，出现了专门强化推理能力的新范式：[⁶](#ref6) [⁷](#ref7)

| 模型 | 厂商 | 核心方法 |
|---|---|---|
| **o1 / o1-pro** | OpenAI (2024.9) | 训练模型在回答前进行长链思考（internal CoT），通过强化学习优化思维链质量 |
| **DeepSeek-R1** | 深度求索 (2025.1) | 纯强化学习（GRPO）激励模型自发产生推理链，无需人工标注 CoT 数据 |
| **QwQ / Qwen3** | 阿里 (2025) | 融合思考模式，支持"thinking"和"non-thinking"切换 |

### 3.4 推理模型的关键特征

1. **显式思维链**：模型在给出最终答案前，先生成（可见或隐藏的）逐步推理过程
2. **更多"思考时间"**：通过生成更多中间 Token 来换取更好的答案质量（test-time compute scaling）
3. **强化学习训练**：通过 RL 奖励正确推理路径，惩罚错误推理
4. **代价**：推理速度更慢、Token 消耗更多、成本更高

### 3.5 传统 LLM vs 推理模型：性能对比

| 基准测试 | GPT-4o（传统） | o1（推理模型） | 提升 |
|---|---|---|---|
| AIME 2024（数学竞赛） | 13.4% | 83.3% | +70% |
| Codeforces（竞赛编程） | 11th percentile | 89th percentile | 显著 |
| GPQA（博士水平科学） | 56.1% | 78.0% | +22% |
| MMLU（通用知识） | 87.2% | 90.8% | +3.6% |

> 关键洞察：推理模型在**需要深度思考**的任务上优势巨大，但在简单知识问答上提升有限。这说明推理模型解决的是"思考深度"问题，而非"知识广度"问题。

### 3.6 Test-time Compute Scaling

传统 Scaling Laws 关注训练阶段的算力投入。推理模型带来了新的范式——**推理阶段（test-time）也可以通过投入更多算力来提升性能**：

- 让模型"想更久"（生成更长的思维链）→ 答案更准确
- 这意味着：同一个模型，给它更多推理时间/Token 预算，就能获得更好的结果
- 用户可以选择"快速但一般"或"慢速但精确"的推理模式

> 就像考试时给你 30 分钟和给你 3 小时，答案质量会不同。推理模型通过"在草稿纸上写出详细推导过程"来提高最终答案的准确率。

### 3.7 正确描述推理能力

- ✅ LLM 可以通过 CoT 和 RL 训练获得**一定程度**的推理能力
- ✅ 推理模型在数学、代码、逻辑任务上**显著超越**普通 LLM
- ❌ "LLM 不具备任何推理能力"——过时的说法
- ❌ "LLM 的推理等同于人类推理"——模型的"推理"本质仍是模式匹配 + 概率生成

## 常见误解

**关于幻觉的根本原因**：
- ❌ "训练数据太少"——数据量是影响因素之一但不是根本原因
- ❌ "模型参数太大"——参数多少与幻觉无直接因果关系
- ❌ "模型没有联网"——联网可以缓解但不能消除幻觉

**关于参数量与性能的关系**：
- ❌ "参数量越大，在所有任务上一定表现越好"——Chinchilla 等研究已证伪

**关于大语言模型的推理能力**：
- ❌ "LLM 完全不能做推理"——已被大量实验证伪
- ❌ "LLM 的推理完全等同于人类逻辑推理"——过度拔高
