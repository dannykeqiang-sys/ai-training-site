# RAG 与幻觉

RAG（检索增强生成）是当前最主流的降低 LLM 幻觉的技术方案，但它并不能完全消除幻觉。理解 RAG 在幻觉治理中的能力边界，是构建可靠 AI 系统的关键认知——既不要低估它的价值，也不要过度信任它。本文从机理层面解释 RAG 为什么能降低幻觉、为什么无法消除幻觉，以及进一步治理的工程实践。

## 一、问题背景：什么是 LLM 幻觉

关于幻觉（Hallucination）的完整定义、根本原因和分类（内在幻觉/外在幻觉），详见本部分《幻觉、参数量与推理能力》。此处仅简述与 RAG 直接相关的要点：

幻觉是 LLM 生成了**看似流畅合理、但实际上不正确或无中生有**的内容。根本原因在于 LLM 本质上是在做**概率性的文字接龙**，并不"理解"事实的真伪。

## 二、RAG 如何降低幻觉

![RAG 降低幻觉但不能消除](https://yk-ai-mentor.youku.com/yk_ai_mentor/tutorials/ch1/images/rag-hallucination-funnel_1784688981.png)

RAG 通过在生成前**注入外部可靠证据**，从两个维度降低幻觉风险：[1](#ref1) [3](#ref3)

### 2.1 提供事实锚点

RAG 将检索到的文档片段塞入 Prompt，让模型在生成时有具体的事实依据可以参考，而不是完全凭"记忆"（参数权重）回答。这相当于让一个人开卷答题，而非闭卷答题。

### 2.2 缩小输出空间

当 Prompt 中明确包含了相关事实，模型的输出分布会被"锚定"在这些事实附近，大幅降低"天马行空"编造的概率。

> **直观比喻**：没有 RAG 时，LLM 像是在完全空白纸上写作文，天马行空；有了 RAG，相当于给了一张写满参考资料的草稿纸，LLM 的作文会围绕这些参考资料展开，跑题的概率大大降低。

### 2.3 实证效果

多项研究表明，RAG 可以**显著降低**幻觉率。例如：
- Lewis et al. (2020) 的 RAG 原论文证明，引入检索后模型在知识密集型任务上的事实准确性大幅提升。[4](#ref4)
- 实际生产中，RAG 系统的幻觉率通常比纯 LLM 低 40%~70%（具体取决于检索质量）。[3](#ref3)

## 三、为什么 RAG 不能完全消除幻觉

![RAG 流水线中的幻觉风险点](https://yk-ai-mentor.youku.com/yk_ai_mentor/tutorials/ch1/images/rag-failure-points_1784689003.png)

**核心认知：RAG 降低（reduce）幻觉，但无法消除（eliminate）幻觉。**

RAG 仍可能产生幻觉的原因至少有以下四种：[3](#ref3) [5](#ref5) [6](#ref6)

### 3.1 检索失败（Irrelevant Retrieval）

如果检索环节未能召回正确的文档——可能因为 query 与文档表述差异大、分块不合理、或知识库中根本没有相关内容——模型拿到的是不相关的片段，在此基础上仍然可能编造答案。

```
用户："公司 2025 年的差旅政策有什么变化？"
检索结果：召回了 2023 年的旧政策文档（2025 年新政策还未入库）
LLM：基于旧文档生成答案，内容过期 → 事实性错误
```

### 3.2 不忠实生成（Unfaithful Generation）

即使检索到了正确的文档，LLM 在生成时仍可能**不忠实于检索到的内容**。模型可能：
- 错误地总结或改写检索片段
- 将多个片段的信息错误地拼接/混淆
- 受自身参数知识的干扰，给出与检索内容矛盾的回答

这是 RAG 幻觉最隐蔽也最危险的来源——答案"看起来"有据可依，但实际上偏离了原文。[5](#ref5)

### 3.3 知识库本身有误（Poisoned/Outdated Knowledge Base）

RAG 的质量上限取决于知识库的质量。如果文档本身包含错误信息、过时内容或互相矛盾的描述，模型"忠实"地引用这些错误内容，同样会产生事实性错误。

### 3.4 上下文窗口限制导致信息丢失

当检索结果较多时，所有片段塞入 Prompt 可能导致关键信息落在模型注意力较弱的"中间"位置（Lost in the Middle 现象），模型因而忽略关键事实。[6](#ref6)

## 四、RAG 幻觉的典型场景举例

为了更直观地理解 RAG 仍会产生幻觉的情形，以下给出三个典型的真实场景：

### 场景 A：检索不相关导致编造

```
用户问题："LoRA 微调的学习率推荐设置多少？"
知识库状态：只包含全量微调的文档，没有 LoRA 相关内容
检索结果：召回了全量微调的学习率建议（1e-5 ~ 5e-5）
LLM 输出："LoRA 微调推荐学习率为 1e-5"
实际正确答案：LoRA 通常使用更高的学习率，如 1e-4 ~ 3e-4

→ 幻觉来源：检索到的内容虽然"相关"（都是微调），但不适用于 LoRA 场景
```

### 场景 B：多片段信息混淆

```
用户问题："张三负责的项目预算是多少？"
检索片段 1："张三负责 A 项目，进展顺利"
检索片段 2："B 项目预算 500 万元，由李四负责"
LLM 输出："张三负责的项目预算是 500 万元"

→ 幻觉来源：模型错误地将片段 2 的预算信息张冠李戴到张三身上
```

### 场景 C：模型参数知识与检索内容冲突

```
用户问题："地球到太阳的距离是多少？"
知识库文档（某科幻小说设定集）："在本故事设定中，地球到太阳的距离为 2 亿公里"
LLM 输出："地球到太阳的距离约为 1.5 亿公里（1 AU）"

→ 幻觉来源：模型的预训练知识覆盖了检索到的文档内容，产生不忠实生成
```

这些场景说明：即使在有检索增强的情况下，LLM 仍可能因为上述原因产生不准确的输出。

## 五、降低 RAG 幻觉的工程实践

虽然无法完全消除，但可以通过以下多层手段进一步降低幻觉风险：[3](#ref3) [5](#ref5)

### 5.1 提升检索质量（治本）

检索质量是 RAG 准确性的基石：

- **优化 Chunking 策略**：语义分块优于固定分块，避免关键信息被切断
- **使用 Hybrid Search**：向量检索 + BM25 双路召回，提升覆盖率
- **加入 Reranking**：Cross-Encoder 精排确保最相关的片段排在最前
- **Query 改写**：对用户问题做扩展或重写，弥合 query 与文档的表述差异

### 5.2 忠实性约束（Prompt 层）

在 System Prompt 中加入明确的生成规则：

```
你是一个严格基于提供的参考文档回答问题的助手。
规则：
1. 只使用 <context> 中的信息回答
2. 如果文档中没有相关内容，回答"根据现有资料无法确定"
3. 不要使用自身的训练知识补充
4. 引用具体的文档片段作为依据
```

### 5.3 引用溯源（Citation / Attribution）

要求模型在回答时**标注每个事实断言的出处**，如 `[来源: 文档A, 第3段]`。这不能直接防止幻觉，但能让用户和系统**快速验证**答案是否有据可依。

### 5.4 后置验证（Post-generation Verification）

| 验证方式 | 机制 | 适用场景 |
|---|---|---|
| **NLI 模型验证** | 用 NLI（自然语言推理）模型判断答案是否与检索内容逻辑一致 | 高精度场景 |
| **LLM-as-Judge** | 用另一个 LLM 评估答案忠实度 | 通用场景 |
| **关键词/实体校验** | 检查答案中的实体是否出现在检索片段中 | 简单快速 |

### 5.5 置信度过滤（Confidence Gating）

对检索结果的相关性评分设置阈值，低于阈值时主动拒绝回答或提示用户"信息不足"：

```
if max_relevance_score < 0.6:
    return "抱歉，知识库中没有找到与您问题高度相关的内容，建议咨询人工客服。"
```

### 5.6 知识库质量管理

- 定期审核和更新文档内容
- 去除重复、矛盾的信息
- 为文档添加时间戳和版本号，检索时优先召回最新版本
- 建立文档质量评估机制

> **推荐实施顺序**：如果你的资源有限，建议按以下优先级逐步建设：第一步，先做好**知识库质量管理**（5.6）——这是基础中的基础，垃圾进必然垃圾出；第二步，优化**检索质量**（5.1），尤其是 Chunking 策略和 Reranking，这直接影响 RAG 的准确率上限；第三步，添加**忠实性约束 Prompt**（5.2）和**引用溯源**（5.3），这两项投入低但能显著提升可信度；第四步，部署**后置验证**（5.4）和**置信度过滤**（5.5），作为最后的安全网。

## 六、RAG 幻觉治理的成熟度模型

| 成熟度 | 措施 | 幻觉率（参考） |
|---|---|---|
| Level 0 | 纯 LLM，无 RAG | 15%~25% |
| Level 1 | 基础 RAG（向量检索 + 拼接） | 8%~15% |
| Level 2 | 高级 RAG（Hybrid Search + Reranking + 忠实性 Prompt） | 3%~8% |
| Level 3 | 带验证的 RAG（后置 NLI 验证 + 置信度过滤 + Citation） | 1%~3% |

> 注：以上数据为行业经验估算，具体取决于场景复杂度和知识库质量。[5](#ref5)

## 七、与"RAG 完全消除幻觉"这一常见误解的辨析

| 说法 | 正确性 | 解释 |
|---|---|---|
| "RAG 可以完全消除幻觉" | **错误** | 检索可能失败、生成可能不忠实 |
| "RAG 能减少幻觉" | **正确** | 通过注入事实证据，显著降低编造概率 |
| "RAG 不需要 LLM" | **错误** | RAG 的 G 就是 Generation，最后一步仍靠 LLM 完成 |
| "RAG 的答案一定有引用所以一定对" | **错误** | 引用的存在不保证答案忠实于引用内容 |
| "RAG 比 Fine-tuning 更准确" | **不一定** | 准确性取决于检索质量和场景适配 |

## 常见误解

- ❌ "RAG 完全消除幻觉"——过于绝对，检索质量、LLM 忠实度、知识库准确性都可能引入幻觉
- ❌ "RAG 不影响幻觉"——忽视了 RAG 通过注入事实证据显著降低编造概率的作用
- ❌ "RAG 增加幻觉"——方向相反，RAG 的核心作用是降低而非增加幻觉
